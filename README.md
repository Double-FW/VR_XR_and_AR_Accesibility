# VR_XR_and_AR_Accesibility

Principles, approaches and methodologies for virtual, augmented and cross reality experiences.

## Overview

This repository is a practical knowledge base for designing, building, testing, and governing accessible and inclusive VR, XR, and AR experiences. It brings together guidance for product owners, industrial designers, interaction designers, content teams, engineers, researchers, procurement teams, and operators.

The materials in this repository are focused on creating experiences that preserve agency, comfort, recovery, and comparable value for disabled and non-disabled users across the full journey of a product or service.

## Included resources

### AGENTS.md

`AGENTS.md` is the repository instruction file for agents and AI systems working on immersive accessibility work. It captures:

- core principles for inclusive VR/XR/AR design
- domain terminology and scope
- design and research methodology
- barrier taxonomy and extended access concerns
- guidance by interaction area (physical ergonomics, input, movement, audio, visual access, cognition, AR, service design)
- acceptance testing and release gates
- governance and decision rules for agent behavior

This is optimized for LLM and agent consumption so that design, engineering, QA, and leadership work remains aligned with accessible practice.

### Inclusive_Design_Guidance_VR_XR_AR.md

This is the primary handbook document in the repository. It contains the detailed guidance, chapters, and test framework covering:

- evidence and scope
- design principles
- research and design methodology
- catalogue of barriers
- physical product and ergonomics guidance
- input and manipulation design
- movement, orientation, and comfort strategies
- visual and nonvisual access
- hearing, speech, and communication
- cognition, learning, and sensory experience
- AR and mixed reality requirements
- design redundancies and competing needs
- software architecture and service design
- performance, reliability, and measurement
- test programme and acceptance criteria
- safe sessions, release, and ongoing improvement
- worked example of an inclusive experience
- sources and evidence notes

## Why this repository matters

XR experiences often fail not because of a single interaction, but because of the interaction between:

- hardware fit and ergonomics
- visual and nonvisual access
- motion comfort and orientation
- input alternatives and timing
- sensory load and cognitive demand
- service and environmental setup
- failure recovery and support

This repository treats accessibility as a product-system concern, not a final-stage polish step.

## Recommended usage

- Start with `AGENTS.md` for agent-facing rules and project conventions.
- Use `Inclusive_Design_Guidance_VR_XR_AR.md` for detailed standards, methods, barriers, and tests.
- Use the handbook as a design and QA reference during:
  - concept and procurement
  - prototyping
  - implementation
  - release validation
  - operations and iteration
